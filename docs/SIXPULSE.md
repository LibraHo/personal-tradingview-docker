# 六脉神剑副图

同时提供「六脉神剑 · 主图上下车」，下文说明主图提示规则。两个版本参数各自独立，可以同时添加。

在「设置 → 指标管理」选择「六脉神剑 · 六项共振」添加。添加后可通过画图工具栏的「指标」快捷开关显示/隐藏。使用独立副图，不允许切到主图以免固定 1–6 排压缩股价尺度。支持已有的图表、周期筛选和指标模板，默认所有周期显示。

从下到上为 MACD、KDJ、RSI、LWR、BBI、MTM。满足比较条件为红色向上箭头，不满足（含相等）为绿色向下箭头；可在配色设置中更改。灰点表示尚不能计算。共振分数 SCORE 是六项满足条件的数量（0–6），全部可计算后才显示；显示在副图标题，不绘制分数曲线。移动十字光标可查看对应 K 线的分数，移出后回到最新值。

## 采用的公式

以用户最后提供的 Mai 版本为准，不是之前的 moomoo Python 版本。

| 排 | 满足条件 | 默认参数 |
| --- | --- | --- |
| MACD | DIFF > DEA | EMA 8、13，信号 EMA 5 |
| KDJ | K > D | 高低窗口 8，SMA 平滑 3、3 |
| RSI | RSI1 > RSI2 | SMA 平滑 5、13 |
| LWR | LWR1 > LWR2 | 高低窗口 13，SMA 平滑 3、3 |
| BBI | CLOSE > BBI | 简单均线 3、6、12、24 的平均 |
| MTM | MMS > MMM | 动量/绝对动量的双 EMA 比值，5/3 与 13/8 |

所有这些周期均可修改。原式虽然声明 `ISDAY:=PERIOD=5`，但画图没有使用 ISDAY，因此不限制日线；如需仅日线显示，在该指标的周期范围中只选日线。

## 明确的计算边界

- `SMA(X,N,1)` 使用 `Y = Y_prev + (X-Y_prev)/N`，不能替换为算术平均或 EMA。EMA 权重为 `2/(N+1)`。
- 递推从首个有效观察值初始化；MA、HHV、LLV 等待完整窗口；首根 REF 不存在时视为缺失。该初始化约定未在用户的 moomoo 运行环境逐根核对，不承诺两端开头数值完全一致。先前 Python 中的 KDJ=50、LWR=−50 初值和不足周期均线不是这次 Mai 移植的默认约定。
- 分母为 0 或必要输入缺失时输出 null，不擅自把未知信号转为绿色，也不计算不完整 SCORE。这是对原式未定义情况的显式处理。
- 使用当前图表实际显示时段的 OHLC 数据，不跨图表读取日线。开关扩展时段、增加更早历史或更改复权数据可能改变结果，递推初值也随加载起点变化。
- 当前未收线 K 线的箭头和分数随行情更新。没有使用未来 K 线；本功能不自动交易，分数不表示胜率或收益率。
- 缩得很密时为避免重叠，按显示间距抽样绘制箭头，计算仍保留每根 K 线；放大后恢复逐根显示。缩小副图高度会影响可读性，可拖动分隔线增高。

## API

现有指标接口支持 `name=SIXPULSE`，参数和时段遵循现有 `/api/indicators` 接口及其认证要求。`values` 返回六项 0/1/null、`SCORE`，以及 `DIFF`、`DEA`、`K`、`D`、`RSI1`、`RSI2`、`LWR1`、`LWR2`、`BBI_VALUE`、`MMS`、`MMM` 诊断序列。诊断数值不作为副图曲线渲染。没有扩展交易策略入口或放宽 Python 沙箱。

这是内置公式移植，平台尚未实现通用 Mai 解析器，也不能直接运行任意 moomoo Python 脚本。

绘图使用 [Lightweight Charts 官方 Series Primitives 接口](https://tradingview.github.io/lightweight-charts/docs/plugins/series-primitives)，没有增加图表库或常驻服务。

## 主图上下车

在指标管理添加「六脉神剑 · 主图上下车」。K 线下方红色箭头标“上车”，上方绿色箭头标“下车”，颜色可改。提示不读取真实持仓，不提交订单，不启动策略。

- 每项可独立勾选。取消 RSI 后，只统计 MACD、KDJ、LWR、BBI、MTM 五项；不会因 RSI 缺值阻止其他五项判断。
- 默认上车为至少 5 红，下车为至少 3 绿。门槛可设为 1 至参与项数；修改参与项时会自动调整门槛到有效范围。红数+绿数门槛必须大于参与项数，避免一根 K 线同时满足相反条件。
- 从所加载历史的“未上车”状态开始：达到上车门槛提示一次，直到达到下车门槛再提示一次，之后允许重新上车。连续满足不会反复提示。该状态只是图表计算，不代表真实账户持仓。
- 任一参与项数据不足时，不发上下车提示，也不把缺失值当作绿色；保留此前图表状态。
- 默认“下一根出现后确认”：最后一根不出提示，下一根到来后才把已确认提示标在产生条件的上一根上。确认不使用新 K 线的价格；跨收盘、午休、停牌等没有新 K 线时会延迟，这是明确的确认规则，不是交易所收线事件。
- 可选择“盘中实时”：允许最新 K 线出现带“盘中”的提示，当前信号可能变化或消失。新数据到来会重新计算，已确认历史也可能因行情校正、增加更早历史、时段范围或参数修改而改变。
- 各项 MACD、KDJ、RSI、LWR、BBI、MTM 周期仍可单独调整，主图版本不会改动副图版本或独立 MACD 的参数。

API 名称为 `SIXPULSE_SIGNAL`。除计算周期外支持以下参数：

```json
{
  "enabled": ["MACD", "KDJ", "LWR", "BBI", "MTM"],
  "enterReds": 5,
  "exitGreens": 3,
  "confirm": "next_bar",
  "fast": 8,
  "slow": 13,
  "signal": 5
}
```

`ENTRY`/`EXIT` 为 1 时产生提示，0 为不提示，null 为无法判断或等待确认；`STATE` 是上述图表状态，非账户持仓；`REDS`、`GREENS` 与主图 `SCORE` 只统计参与项。`confirm` 也可设为 `live`。其他六项和诊断序列保留，全部返回数据序列，不含交易指令。

## 验证范围

2026-11-06：12 项六脉测试与 27 项现有指标测试通过；280 组整体前后端对照及额外自定义参数对照通过。独立审查枚举 1,344 种参与项、门槛与确认方式组合，其中 864 种有效组合计算一致，冲突组合均被拒绝。

Edge 桌面 1440×900、窄屏 390×844 检查了添加、参数验证、排除 RSI、颜色、周期筛选、确认方式、快捷开关、刷新持久化和行情更新。浏览器回放来自此前 NAS 的真实历史 K 线，API 与配置保存隔离，未覆盖真实用户配置。副图首次部署后的实际 NAS API 另外读取了 SNDK 2,304 根 5 分钟 K 线，`stale=false`，MACD 和 RSI 参数修改生效。moomoo 同一批 K 线逐根输出尚未提供，因此这些结果不证明两端数值完全一致。

主图版实际 NAS API 同样通过：SNDK 2,304 根 5 分钟数据，`stale=false`；使用排除 RSI、4 红上车/3 绿下车、MACD 快线 6 的验证配置，逐根核查五项计数、提示交替和末根待确认。测试没有修改用户工作区、下单或重启 OpenD。主图标记使用 [官方 createSeriesMarkers](https://tradingview.github.io/lightweight-charts/docs/api/functions/createSeriesMarkers)。
