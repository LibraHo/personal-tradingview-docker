# NAS Market OpenD 连接与登录

目标：在顶部连接状态和统一设置提供 OpenD 登录 UI，用户手动输入账号、密码和验证码，NAS 重启后无需打开 SSH 窗口。

采用现有 OpenD 容器内的 Python 标准库 supervisor：以 PTY 运行原 OpenD 10.11.7108，按实际中英文提示识别登录阶段。平台只通过私有 Unix socket 调用固定动作。相比挂载 Docker socket 的网页终端，此方案不向 Market 授予容器管理权限；相比在网页开放 Telnet，此方案不暴露通用命令行。现有 OpenD 行情端口、RSA、home 挂载和运行版本保持原样。

安全边界：仅 HTTPS 平台会话可调用 /api/trade/opend/*，沿用 Origin、CSRF、会话失效机制；绘图 Token 无权调用。禁止通用命令，输入拒绝换行和控制字符，以阶段随机 revision 防止重复及过期提交。浏览器关闭或阶段变化清空输入。平台不保存账号密码，不打印原始 OpenD 控制台，仅提供固定状态及经分类的错误。默认向“记住密码”提示回答 N。图形验证码仅允许读取固定 OpenD 数据目录内的图片，限制大小及文件类型。

状态面板在打开期间轮询私有 socket，关闭即停止；不添加后台行情订阅。面板只显示适配器观察到的登录阶段，实时行情连接仍由页顶的原有状态接口显示，不把登录成功提示当作持续网络连通证明。重启登录仅在异常/未完成登录阶段提供，服务器检查未启用策略、无待补挂保护和不明下单状态，再允许重启 OpenD 子进程。

部署增加两个可选 Compose overlay：OpenD 挂载 supervisor 和私有 socket 目录；Market 挂载同一 socket 目录。不新增常驻容器，保持 restart 策略，日志与内存均有界。原 Compose 及程序、设备状态保留回退备份。

验证：阶段解析及分包、重复/过期提交、命令注入、错误脱敏、重启保护、HTTPS/认证/CSRF/绘图 Token 隔离；前端构建与 Edge 浏览器检查入口、分阶段输入、错误和登录成功状态。真实 OpenD 重启提示验证及由用户亲自输入账号密码完成端到端验证，不在测试脚本中存放实际凭据。
