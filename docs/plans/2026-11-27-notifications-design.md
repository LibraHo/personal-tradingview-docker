# 通用 HTTP 通知设计

最终要求：不内置服务商，管理员填写地址。设置页支持多个POST渠道，配置URL、秘密请求头、JSON/表单编码、标题/正文字段名、附加普通字段和JSON成功条件。地址及请求头保存后不回显。入口仅HTTPS登录会话开放，写入需要同源和CSRF。

数据链路：原任务按自身间隔或指定时间检查行情 → scan_events → Notifications筛选monitor_ids/confirmation → 持久outbox → 通用send_webhook。通知模块不连接OpenD，不增加实时订阅。其他事件生产者可调用enqueue(db,channel,event_id,{title,body})，事务由调用者管理。

每渠道从创建时最新游标开始，不补历史；空列表不接收全部监控。事件入队与推进游标同一事务，(channel_id,event_id)唯一。停用/删除/调整接收范围取消待发消息。修改名称、请求配置或预算保留队列；已发出的请求无法撤回。

发送前持久化sending和预算，HTTP2xx或可选JSON成功值匹配后标记accepted（不等于已读）。明确拒绝最多请求三次；超时、坏回执、重启时遗留sending均标记unknown，不盲目重发，不声称exactly-once。

每渠道每日1–1000次上限，按北京时间自然日重置；测试和重试共用预算，请求最小间隔2秒。到限留至次日。手动测试30秒冷却，不堆积。远端账户可能多个渠道共用，本地预算不是服务商余额。

支持管理员明确配置的HTTP（包括内网）或HTTPS；禁止URL用户名密码、片段和控制字符，参数须URL编码。禁止跳转，不转发平台Cookie或会话。换目标时需重新填写旧请求头或明确清空，防止转发旧目标凭证。接收端错误正文、请求地址和请求头不进入日志。秘密存储于服务端SQLite专用表，沿用NAS目录权限；备份按含密钥文件保管。

验证：事件筛选、重启去重、真实扫描器事件、重试/未知结果、预算、地址/头保密、换地址清理鉴权、表单与JSON字段、自定义成功条件、本地HTTP接收器真实请求、HTTPS认证和CSRF、前端构建及表单操作。真实微信到达需用户配置后点击测试并核对手机。
